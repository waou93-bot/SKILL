# Extensions optionnelles : llms.txt, Markdown, OKF et outils d'agents

Ce fichier remplace l'ancienne prescription d'ajouter des bundles supposés favoriser tous les
moteurs. Distinguer lisibilité, distribution par une intégration et acquisition organique.

| Extension | Décision |
|---|---|
| llms.txt | Proposition de format à relire chez son auteur ; utile seulement si un consommateur identifié l'utilise. Pas de promesse d'adoption universelle ni de classement. |
| Markdown / JSON public | Export facultatif d'une vérité déjà publique ; source unique, synchronisation, types et cache contrôlés. |
| OKF ou autre bundle | Expérience ou besoin documentaire identifié : vérifier auteur, version et consommateur avant conception. Aucun rôle de SEO confirmé ici. |
| API / MCP / WebMCP | Interface d'usage d'un agent, pas soumission automatique dans tous les moteurs. Vérifier le protocole et les capacités actuelles. |
| Flux marchand / protocole commerce | Vérifier marchand réel, éligibilité, pays, fraîcheur catalogue, contrats et intégration ; ne pas le proposer par défaut à un affilié. |
| AGENTS.md | Instructions du dépôt pour un agent de code ; ne pas publier un prétendu ordre aux moteurs de recommander le site. |

Avant une extension : besoin, utilisateur/agent consommateur, documentation primaire actuelle,
alternative plus simple, coût de maintien, données publiques, test, critère de succès et rollback.
Si aucun consommateur ni gain utile n'est démontrable, différer. Pas de priorité P0 automatique.

Google indique que ses fonctionnalités Search n'utilisent pas llms.txt comme signal et n'exigent
pas de fichiers IA particuliers ; ne pas extrapoler ce constat à tous les outils. Pour les autres
plateformes, absence de preuve d'un effet de classement = inconnu, pas « forcément efficace ».

Sources : [registre](sources.md), notamment la documentation Google et llmstxt.org. Ne pas copier
une ancienne version du format comme si elle était toujours la spécification actuelle.
